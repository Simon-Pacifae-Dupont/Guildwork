Un vrai test de la passation

Ce qui a cassé

Une session a été fermée, le contexte effacé, et une nouvelle session ouverte sur la même branche. L'état Git a survécu parfaitement. La nouvelle session a retrouvé la branche, la tête, la pull request — et une priorité globale vieille de trois sprints. Les causes racines d'un audit, le lot suivant qu'il recommandait et la décision qui le bloquait ont dû être reconstitués à la main depuis un journal, une pull request, le dépôt et de vieux dossiers de travail ; une partie n'était pas récupérable du tout.

La règle qu'il a payée

Si une nouvelle session oblige l'humain à répéter du contexte opérationnel récent, le système de continuité a échoué. L'entrée lit le journal ; le journal se lit avant la passation rédigée.
